1. OVERVIEW PROJECT KOSTIFY
================================================================================

Kostify adalah aplikasi Flutter untuk manajemen kos dengan fitur:
  • Authentikasi pengguna (Tenant & Admin)
  • Manajemen pembayaran (integrasi Midtrans)
  • Scan KTP otomatis dengan OCR (Google ML Kit)
  • Chat AI assistant (Gemini)
  • Emergency alert system (Telegram)
  • Payment reminder (WhatsApp)
  • Mapping lokasi kos
  • Broadcast pengumuman
  • Dashboard real-time

Tech Stack:
  • Frontend: Flutter (Dart)
  • Database: SQLite (Local)
  • Backend: REST API
  • Payment Gateway: Midtrans Snap
  • OCR: Google ML Kit Text Recognition
  • AI: Google Gemini
  • State Management: GetX
  • HTTP Client: http package

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File yang terlibat:
  • views/auth/login_screen.dart           (UI - form login)
  • controllers/auth_controller.dart       (State management)
  • services/database_helper.dart          (Query user dari database)
  • models/user_model.dart                 (Data structure)

ALUR LOGIN:
──────────
  1. User input username & password di login_screen.dart
  
  2. Click "Login" button
     └─→ Call: _loginUser() function
  
  3. _loginUser() melakukan:
     • Validasi input (username & password tidak kosong)
     • Show loading dialog
     • Call: auth_controller.login(username, password)
  
  4. AuthController.login() melakukan:
     • Query database via: DatabaseHelper.getUserByUsername(username)
     • Verifikasi password (cocok atau tidak)
     • Jika cocok:
       └─→ Save user ke SharedPreferences (session)
       └─→ Get role (tenant/admin) dari UserModel.role
       └─→ Return true
     • Jika tidak cocok:
       └─→ Return false dengan error message
  
  5. Jika login berhasil:
     • Close loading dialog
     • Navigate ke dashboard sesuai role:
       ├─ role == 'tenant'  → tenant_dashboard_screen.dart
       └─ role == 'admin'   → admin_dashboard_screen.dart
  
  6. Jika login gagal:
     • Show SnackBar dengan error message
     • User tetap di login screen

DATA FLOW:
──────────
  UI Form Input (username, password)
    ↓
  AuthController.login()
    ↓
  DatabaseHelper.getUserByUsername()
    ↓
  Query SQLite: SELECT * FROM users WHERE username = ?
    ↓
  UserModel returned (if exists)
    ↓
  Password verification
    ↓
  Save session → SharedPreferences
    ↓
  Navigator.pushReplacementNamed() to dashboard

ERROR HANDLING:
───────────────
  ❌ User tidak ditemukan → "Username atau password salah"
  ❌ Password tidak cocok → "Username atau password salah"
  ❌ Input kosong → "Username dan password tidak boleh kosong"

ENUM PaymentStatus:
───────────────────
  enum PaymentStatus {
    paid,      // ✓ Sudah dibayar
    pending,   // ⏳ Belum dibayar
    overdue    // ⚠️ Terlambat
  }

MODEL PaymentModel:
───────────────────
  class PaymentModel {
    id?: int                    // Primary key
    userId: int                 // Foreign key ke users table
    amount: int                 // Jumlah dalam Rupiah
    status: PaymentStatus       // paid/pending/overdue
    bulan: string (yyyy-MM)     // Format: "2025-06" untuk Juni 2025
    createdAt: DateTime?        // Tanggal tagihan dibuat
    paidAt: DateTime?           // Tanggal pembayaran masuk
    keterangan: string?         // Catatan (misal: "Sewa bulan Juni 2025")
    orderId: string?            // ⭐ Midtrans order ID (ORDER-userId-timestamp)
    snapUrl: string?            // ⭐ Midtrans Snap redirect URL
  }

STEP 3: GENERATE ORDER ID & PANGGIL MIDTRANS API
┌──────────────────────────────┐
│ ApiService.getMidtransSnapUrl()
│
│ PARAMETER INPUT:
│ ├─ orderId: "ORDER-123-1715000000000"
│ ├─ amount: 500000
│ └─ customerName: "John Doe"
│
│ LOGIC INSIDE:
│ ├─ Check internet connection
│ │  ├─ If no internet → Return error
│ │  └─ If connected → Continue
│ │
│ ├─ Validate Midtrans credentials dari constants.dart
│ │  ├─ MIDTRANS_SERVER_KEY must exist
│ │  ├─ MIDTRANS_CLIENT_KEY must exist
│ │  └─ If not → Return error
│ │
│ ├─ Encode server key ke Base64
│ │  └─ "MIDTRANS_SERVER_KEY:" → Base64
│ │  └─ Format: "Authorization: Basic {base64_encoded}"
│ │
│ ├─ Build HTTP request payload:
│ │  {
│ │    "transaction_details": {
│ │      "order_id": "ORDER-123-1715000000000",
│ │      "gross_amount": 500000
│ │    },
│ │    "customer_details": {
│ │      "first_name": "John Doe",
│ │      "email": "kostify-tenant@kos.local",
│ │      "phone": "62812345678"
│ │    },
│ │    "callbacks": {
│ │      "finish": "https://app.example.com/payment-finish"
│ │    }
│ │  }
│ │
│ └─ HTTP POST to Midtrans
│    ├─ URL: https://api.sandbox.midtrans.com/v2/transactions
│    ├─ Headers: 
│    │   ├─ Authorization: Basic {encoded_key}
│    │   └─ Content-Type: application/json
│    ├─ Body: JSON payload di atas
│    ├─ Timeout: 30 seconds
│    │
│    └─ RESPONSE dari Midtrans:
│       ├─ Status 201 (Created): SUKSES
│       │  └─→ Response: {
│       │      "redirect_url": "https://app.midtrans.com/snap/v1/XXX",
│       │      "token": "token_snap_1234567890",
│       │      "expiry": 1715086400
│       │    }
│       │  └─→ Return MidtransResult.success(redirect_url)
│       │
│       ├─ Status 401 (Unauthorized): GAGAL
│       │  └─→ Credentials invalid
│       │  └─→ Return MidtransResult.error("Kredensial tidak valid")
│       │
│       ├─ Status 400 (Bad Request): GAGAL
│       │  └─→ Parameter validation error dari Midtrans
│       │  └─→ Return MidtransResult.error(validation_message)
│       │
│       └─ Other errors: GAGAL
│          └─→ Return MidtransResult.error(error_message)
└──────────────────────────────┘

STEP 4: UPDATE DATABASE & BUKA BROWSER

└──────────────────────────────┘

STEP 5: USER MEMBAYAR DI MIDTRANS
┌──────────────────────────────┐
│ Midtrans Snap Payment Gateway
│
│ User action di browser Midtrans:
│ ├─ Select payment method (e.g., Credit Card)
│ ├─ Enter payment details (e.g., card number, CVV)
│ ├─ Midtrans process payment dengan bank/payment provider
│ │  ├─ Fraud detection
│ │  ├─ 3D Secure verification (jika diperlukan)
│ │  └─ Card validation
│ ├─ Payment success/failed
│ └─ Browser redirect ke finish page
│    └─→ Display: "Pembayaran berhasil" atau "Pembayaran gagal"
└──────────────────────────────┘

STEP 6: SYNC PAYMENT STATUS (ASYNCHRONOUS)
┌──────────────────────────────┐
│ Sometime later (bisa manual atau auto)
│
│ _syncMidtransPayments() dipanggil:
│ ├─ Loop melalui semua pending payments di database
│ │  └─→ SELECT * FROM payments WHERE status = 'pending'
│ │
│ ├─ For each pending payment:
│ │  └─→ Call: checkMidtransTransactionStatus(orderId)
│ │      │
│ │      └─→ ApiService.checkMidtransTransactionStatus(orderId)
│ │          │
│ │          ├─ HTTP GET request ke Midtrans
│ │          │  ├─ URL: https://api.sandbox.midtrans.com/v2/{orderId}/status
│ │          │  ├─ Headers: Authorization: Basic {encoded_key}
│ │          │  └─ Timeout: 30 seconds
│ │          │
│ │          └─ RESPONSE dari Midtrans:
│ │             ├─ Status 200/201: OK
│ │             │  └─→ Response JSON contains: {
│ │             │      "transaction_status": "settlement",  ← Status pembayaran
│ │             │      "order_id": "ORDER-123-1715000000000",
│ │             │      "gross_amount": 500000,
│ │             │      "payment_type": "credit_card",
│ │             │      "transaction_time": "2025-05-05 10:30:00",
│ │             │      "status_code": "200"
│ │             │    }
│ │             │
│ │             │  Possible transaction_status values:
│ │             │  ├─ "settlement"   → PEMBAYARAN SUKSES (dana diterima)
│ │             │  ├─ "capture"      → PEMBAYARAN SUKSES (untuk kartu kredit)
│ │             │  ├─ "pending"      → Menunggu konfirmasi
│ │             │  ├─ "cancel"       → Pembayaran dibatalkan
│ │             │  ├─ "deny"         → Pembayaran ditolak
│ │             │  ├─ "expire"       → Pembayaran expired
│ │             │  └─ "failure"      → Pembayaran gagal
│ │             │
│ │             └─ If status is "settlement" or "capture":
│ │                 └─→ UPDATE payment di database
│ │                     └─→ UPDATE payments SET 
│ │                         status = 'paid',
│ │                         paid_at = NOW()
│ │                         WHERE id = ?
│ │
│ ├─ Refresh UI untuk show updated status
│ └─→ Tenant akan lihat: "✓ Lunas" (Paid) dengan checkmark
│    atau Admin akan lihat status payment berubah ke PAID
└──────────────────────────────┘

STEP 6: CROP IMAGE TO GUIDE BOX
┌──────────────────────────────┐
│ _cropToGuideBox(              │
│   compressedBytes             │
│ )                             │
│                              │
│ Tujuan: Hanya ambil bagian    │
│ KTP, buang latar belakang     │
│                              │
│ LOGIC:                       │
│ ├─ Decode image bytes        │
│ ├─ Calculate target aspect:  │
│ │  └─ const targetAspect = 1.58 (KTP ratio)
│ │                            │
│ ├─ Calculate crop dimensions:│
│ │  ├─ cropWidth = img.width * 0.88
│ │  ├─ cropHeight = cropWidth / 1.58
│ │  │                            │
│ │  └─ Max height = img.height * 0.72
│ │     └─ If calculated height > max:
│ │        └─ Use max height instead
│ │                            │
│ ├─ Calculate crop position:  │
│ │  ├─ x = (img.width - cropWidth) / 2
│ │  ├─ y = (img.height - cropHeight) / 2
│ │  └─ Center crop di tengah image
│ │                            │
│ ├─ Crop image:               │
│ │  └─ img.copyCrop(           │
│ │      source,               │
│ │      x: x,                 │
│ │      y: y,                 │
│ │      width: cropWidth,     │
│ │      height: cropHeight    │
│ │    )                       │
│ │                            │
│ └─ Encode back to JPEG       │
│    └─ img.encodeJpg(cropped, quality: 80)
│                              │
│ Result: Uint8List cropped_bytes
└──────────────────────────────┘

┌──────────────────────────────┐

│                              │

│ └─ Result: Text regions found
│                              │
│ PHASE 2: Character Recognition
│ ├─ Untuk setiap text region:│
│ │  ├─ Apply neural network  │
│ │  ├─ Recognize individual  │
│ │  │  characters            │
│ │  └─ Build text string     │
│ │                            │
│ └─ Result: Recognized text  │
│                              │
│ PHASE 3: Bounding Box Calculation
│ ├─ Untuk setiap line & block:
│ │  ├─ Calculate position on │
│ │  │  image (x, y, width,   │
│ │  │  height)               │
│ │  └─ Store dalam rect      │
│ │                            │
│ └─ Result: Text dengan posisi
│                              │
│ Result: RecognizedText object
│ {                            │
│   blocks: [                 │
│     TextBlock {             │
│       lines: [             │
│         TextLine {         │
│           text: "NIK",     │
│           boundingBox: Rect(...),
│           elements: [...]  │
│         },                 │
│         TextLine {         │

│           boundingBox: Rect(...),

DATA FLOW OCR:
───────────────
  Captured Image (from camera/gallery)
    ↓
  FlutterImageCompress (JPEG 80%, auto-fix EXIF)
    ↓
  _cropToGuideBox (center crop, 88% width, 72% height)
    ↓
  Save temp file for ML Kit
    ↓
  TextRecognizer.processImage()
    ↓
  ML Kit OCR Processing:
    ├─ Text Detection
    ├─ Character Recognition
    └─ Bounding Box Calculation
    ↓
  RecognizedText object returned
    ↓
  _parseKTPResult():
    ├─ Sort lines by vertical position
    ├─ Find labels (NIK, NAMA, ALAMAT)
    └─ Extract values by alignment
    ↓
  Extracted: {nik, nama, alamat}
    ↓
  setState(): Update form fields
    ↓
  Display to admin with debug boxes
    ↓
  Admin verifies & clicks "Lanjut"
    ↓
  Continue to next form step

POSSIBLE ERRORS & HANDLING:
────────────────────────────
  ❌ Camera not available
     └─→ Set _error = "Kamera tidak tersedia"
     └─→ Show message to user
  
  ❌ Permission denied
     └─→ _error = "Izin kamera belum diberikan"
     └─→ Ask user to enable permission
  
  ❌ Image compression failed
     └─→ Exception caught
     └─→ _ocrError = "Gagal memproses gambar"
     └─→ Suggest retake photo
  
  ❌ OCR result empty
     └─→ recognized.text.trim().isEmpty
     └─→ _ocrError = "Gambar tidak terbaca. Pastikan KTP jelas..."
     └─→ Suggest better lighting or retake
  
  ❌ Extraction failed
     └─→ If NIK/Nama/Alamat empty
     └─→ Fallback to raw text
     └─→ Or let admin fill manually
  
  ❌ File operations failed
     └─→ Cleanup temp files in catch block
     └─→ Try-catch untuk delete operations

  int? id;                      // Primary key

  String password;              // Hashed password
  String? namaLengkap;          // Full name (extracted from KTP)
  String? nik;                  // ID number (extracted from KTP)
  String? alamat;               // Address (extracted from KTP)
  String? telepon;              // Phone number
  String? nomorKamar;           // Room number
  int? hargaSewa;               // Monthly rent (in Rupiah)
  String? tanggalMasuk;         // Date moved in (yyyy-MM-dd)
  String role;                  // 'tenant' atau 'admin'
  DateTime? createdAt;          // Account creation date
  DateTime? updatedAt;          // Last update

  Methods:
  + toMap() → Map<String, dynamic>  (for database)
  + fromMap(Map) → UserModel        (from database)
  + copyWith() → UserModel          (create copy with updates)
}

class PaymentModel {
  int? id;                      // Primary key
  int userId;                   // Foreign key → users.id
  int amount;                   // Amount in Rupiah
  PaymentStatus status;         // paid/pending/overdue
  String bulan;                 // Format: "2025-06" (year-month)
  DateTime? createdAt;          // Bill creation date
  DateTime? paidAt;             // Payment received date
  String? keterangan;           // Notes/description
  String? orderId;              // Midtrans order ID (auto-generated)
  String? snapUrl;              // Midtrans Snap redirect URL
}

enum PaymentStatus {
  paid,                         // ✓ Paid
  pending,                      // ⏳ Waiting for payment
  overdue                       // ⚠️ Late payment
}

CREATE TABLE payments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  amount INTEGER NOT NULL,
  status TEXT DEFAULT 'pending',  -- 'pending', 'paid', 'overdue'
  bulan TEXT NOT NULL,            -- Format: "2025-06"
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  paid_at TIMESTAMP,
  keterangan TEXT,
  order_id TEXT,                  -- Midtrans order ID
  snap_url TEXT,                  -- Midtrans Snap URL
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
  UNIQUE(user_id, bulan)          -- One payment per tenant per month
);

🔗 Midtrans Payment Gateway
────────────────────────────
Base URL: https://api.sandbox.midtrans.com (Sandbox mode)

Endpoints:
1. Create Snap Transaction
   ├─ Method: POST
   ├─ Path: /v2/transactions
   ├─ Auth: Basic Auth (ServerKey:)
   ├─ Request Body:
   │  {
   │    "transaction_details": {
   │      "order_id": "ORDER-123-1715000000000",
   │      "gross_amount": 500000
   │    },
   │    "customer_details": {
   │      "first_name": "John Doe",
   │      "email": "email@example.com",
   │      "phone": "62812345678"
   │    },
   │    "callbacks": {
   │      "finish": "https://app.example.com/payment-finish"
   │    }
   │  }
   └─ Response: { redirect_url, token, expiry }

2. Check Transaction Status
   ├─ Method: GET
   ├─ Path: /v2/{orderId}/status
   ├─ Auth: Basic Auth (ServerKey:)
   └─ Response: { transaction_status, order_id, amount, payment_type }

Possible transaction_status:
  • settlement / capture → Payment SUCCESS
  • pending → Waiting for confirmation
  • cancel / deny → Payment CANCELLED/DENIED
  • expire → Payment expired
  • failure → Payment FAILED

Credentials (from .env):
  • MIDTRANS_SERVER_KEY: Get from https://dashboard.sandbox.midtrans.com
  • MIDTRANS_CLIENT_KEY: Get from dashboard above

}

KESIMPULAN: HOW DATA FLOWS THROUGH KOSTIFY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. USER ACTION (UI)
   └─→ Widget button/form di views/

2. STATE MANAGEMENT (Controllers & Services)
   └─→ GetX controllers atau Service classes
   └─→ Handle business logic & validation

3. DATABASE OPERATIONS (SQLite)
   └─→ DatabaseHelper execute queries
   └─→ Data saved/retrieved from local database

4. EXTERNAL API CALLS (if needed)
   └─→ ApiService make HTTP requests
   └─→ Midtrans, Gemini, Telegram, etc

5. RESPONSE HANDLING
   └─→ Parse response
   └─→ Update database if needed
   └─→ Update UI state

6. UI REFRESH
   └─→ setState() atau Obx() update UI
   └─→ Show success/error messages

This is the basic flow for every feature in Kostify!
